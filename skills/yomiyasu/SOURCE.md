## 審査

2026-10-20 に固定コミットを runtime の外（`~/.local/share/skill-governance/quarantine/nanaism-yomiyasu/8be3ef6e0e668f14cae30c3da6b0c20b95b2179f/repo`）へ取得し、実行前に次を行った。

- 静的検索: 5本のスクリプトに、通信のモジュール、`eval` / `exec` / `compile`、`pickle` / `marshal`、`shell=True` はない。
- 独立レビュー2本（スクリプトの全体、SKILL.md と references の全体）。CRITICAL の指摘はなく、どちらも「条件付きOK」。
  - スクリプト: `yomiyasu_check.py` の `run` が子プロセスを動かす。動かすのは同梱の lint と diff だけで、引数は許可リストで決め、`shell=True` はない。書き込み先は状態フォルダだけで、実行IDとハッシュは全経路で検証している。
  - SKILL.md と references: 隠れた指示、通信、パッケージの導入、設定の書き換えはない。依頼にない文書を読む動作は、名前だけで呼ばれたときの作業フォルダ直下の `.md` / `.txt` の一覧と、裏取りでの名前の出たファイル（3つまで）に限られる。

1.0.8 までと違い、`yomiyasu_check.py` は状態フォルダへ書き込む。lint と diff は従来どおり読むだけ。

## 運用条件

審査の条件を、上流のファイルを改変せずに運用で守る。

1. `yomiyasu_check.py` の `run` と `verify` は、`--state-dir "$TMPDIR/yomiyasu-state"` を付けて実行する。既定の `.yomiyasu/`（git の最上位）には原文と最終稿の全文の写しが残り、Vault では obsidian-git が拾う恐れがある。
2. 最終稿と `.material.txt` は、Vault とリポジトリの外（`$TMPDIR`）に置く。
3. 実行は `python3 -I -B`。check の子プロセスは `-I` を付けず環境変数を引き継ぐので、`PYTHONPATH`、`PYTHONHOME`、`PYTHONUSERBASE` を設定しない。
4. 第三者のリポジトリで使うときは、`.yomiyasu` がリンクでなく、既存の中身がないことを確かめるか、新しい `--state-dir` を指定する。
5. 記録は消す機能がなく、全文の写しが残る。社外秘は `--no-record` を使うか、`$TMPDIR` 配下に置いて終わったら消す。
6. 処理時間の上限（`--timeout`）が効くのは子プロセスだけ。長い入力では呼び出し側で時間を区切る。
