# 初学者向けexplainerの型

前提知識のない読者に一つのドメインを最後まで把握させるための、章立て、アナロジー、絵の型を定める。`technical-explainer` の上に重ねる既定であり、ユーザーが「例え話を入れて」「絵にして」と言わなくても適用する。

## 発火条件

次のどれかに当たれば適用する。

- 依頼が「〜とは何か」「仕組みを教えて」「ドメインを把握したい」の形をしている。
- 読者が「前提知識がない」「まっさら」「初めて」と書かれている、または依頼文からそう読める。
- 読後の目的が判断ではなく理解で、対象が3つ以上の主体や段階を持つ。

change-review、decision-plan、実務者向けの仕様説明には適用しない。読者像が曖昧なときは「読者: 誰が読むか」の一文で決め、metaに残す。

## 章立ての既定

`technical-explainer` の推奨順序に、次を組み込む。

1. 一文の結論と読む順（decision bandの右側に「全体像 → 用語 → 1件を追う → 歴史 → 詳細」の順を置く）。
2. orientationと、場面の絵としてのoverview。続けて登場人物の地図。
3. 身近な例で掴む章。三つ程度の日常の例を並べ、同型であることを絵で示す。
4. 最小用語の表。各用語に「図1の位置」と「なぜこの語が要るか」の列を持たせる。
5. 代表ケースの時系列。仮設と明示した数字で、1件が最初から最後まで流れる。
6. なぜ生まれたか。歴史、以前の方法、何を解いたか、何が難しくなったか、昔と今の比較表。
7. 詳細章（仕組み、お金と記録の流れ、比較対象、周辺の仕組み）。各章に絵を一枚。
8. うまくいかないとき。失敗の入口から終点までを階段で描く。
9. 規制・制度。as of日付と出典つきの表。
10. 似た言葉の整理。
11. 自己テスト。問いと答えを並べ、答えは隠さない。
12. 出典。一次、二次、内部ノート、解釈を区別する。

右railは目次と用語集にする。用語集は本文で初出時に短く説明した語を参照用にまとめる。

## アナロジーの規則

- 主要章ごとに `.analogy` の囲みを一つ置く。見出しは「たとえるなら」。
- 囲みの末尾に「比喩の限界」を必ず書く。どこで比喩が崩れ、専門の仕組みが必要になるかを一文で示す。この一文が次の章への導線になる。
- 比喩は読者が全員経験しているものから選ぶ（家計、給料、光熱費、図書館、家賃、貸し傘、商品券など）。業界の別の専門用語で言い換えない。
- 一つの比喩を複数章で再利用してよい。歴史の章で出した具体例（実在の企業や慣行）は、後の章の根拠として繰り返し参照する。
- 比喩のためだけに数字や人物を創作しない。数字を使う場合は「仮設」と明示する。

## 絵の型

各型は一枚のinline SVGで描く。図番号は章番号ベース（第6章の一枚目は図6a）にし、overviewだけ図1、図1bとする。

| 型 | 答える問い | 描くもの |
|---|---|---|
| 場面の絵（scene overview） | 全体で何が誰から誰へ動くか | 当事者を建物や人の形で左右に置き、モノ・書類・お金の流れを上下の段に分けて矢印で描く。両側に記録（帳簿など）を置き、待つ期間と失敗の行き先を下段に置く。番号①〜⑤・S・Fを本文で再利用する |
| 登場人物の地図 | 周りに誰がいて、何を手伝うか縛るか | 中央に当事者、周囲に6程度の主体。各箱に役割一文と、担当する番号と章番号 |
| 同型並列 | 身近な例と同じ形か | 三つの例を行に並べ、同じ三段（先に受け取る → 記録して待つ → まとめて払う）を列に揃える |
| 両端 | 二つの用語は同じものか | 一本の線の両端にラベルを置き、線が切れる条件を書く |
| 昔と今の帯 | 何が変わり何が変わっていないか | 同じ長さの期間の帯を上下に置き、印の数や間隔の違いで見せる |
| ものさし・bar | どこまで許すか、いくらまでか | 目盛りと閾値、段階（A〜E）、使用量と上限のbar |
| 資金の穴 | いつ出て、いつ戻るか | 時間軸に出金と入金の矢印を置き、その間を帯で塗る。対比として裏返した例を下段に置く |
| 下りの階段 | 悪化するとどうなるか | 左上から右下へ段を下り、各段に手段と時期。途中で戻れる経路を破線で描く |
| before / afterの帯 | 制度や変更で何が消えたか | 旧と新の期間の帯を上下に置き、消えた区間を破線枠で示す |

## 描き方の規則

- viewBox幅は1000を基準にし、高さは内容で決める。文字は基本20px、補助15px、矢印ラベル14px。日本語1文字はfont-sizeとほぼ同じ幅で見積もり、箱に入る文字数を先に数える。
- 箱の中の文は2行までにし、長い説明はcaptionか本文へ逃がす。
- 色は本文と同じ3系統だけにする。品物・書類の動きはink、お金の動きはaccent、失敗はwarning。色だけに意味を持たせず、実線・破線・ラベルでも区別する。
- アイコンは基本図形（rect、polygon、circle、line）の組み合わせで描く。建物、箱、書類、硬貨、銀行、帳簿の程度で十分で、装飾を増やさない。
- 各SVGに `role="img"`、`title`、`desc`、`figcaption` を付ける。`desc` は絵を見ない読者が同じ内容を追える文章にする。
- markerは最初のSVGで定義し、同じ文書内の後続SVGから参照する。idは文書全体で重複させない。
- 描いた後に、textのbbox同士の重なり、囲みrectからのはみ出し、viewBox外を機械検査し、0にしてから目視する。検査方法は `validation.md` に置く。

## template側の部品

`assets/editorial-document.html` には次のcomponentを用意している。

- `.analogy`: 「たとえるなら」と `.limit`（比喩の限界）。
- `.caution`: 境界や法的な注意を置く囲み。
- `.step-list`: 代表ケースを番号つきで追う一覧。
- `.qa`: 自己テストの問いと答え。
- `.scene`: 場面の絵に使うSVGの文字設定。
