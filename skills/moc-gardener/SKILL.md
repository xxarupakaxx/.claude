# /moc-gardener

まず `CLAUDE.md` と適用対象の運用規則を読み、追記のみ、新規は Inbox 配下、`Claude-note/` 不可侵に従う。[[weekly-learning-review]] が当週の新規だけを見るのに対し、これは全量を月次または随時に点検する。

## 到達性を判定する

- MOC 集合：[[AI-Agent-MOC]]、[[LayerX入社準備-MOC]]、[[Concepts-MOC]]、[[Paymentドメイン基礎マップ]]。
- 対象：`Inbox/knowledge/` の全ノート（README と MOC 自身を除く）。
- 本文の `[[wikilink]]` と frontmatter の `related` から無向グラフを作り、MOC 集合からの距離をスクリプトで測る。
- 距離1は直接リンク、距離2は概念ノート経由、距離3以上または到達不能を接続漏れ候補とする。件数を目視で数えない。

## 候補の処遇

各候補を一つだけ選ぶ。

1. **接続する**：既存 MOC のクラスタに合うとき、MOC のクラスタとノート末尾の「🔗 関連」へ MOC リンクを追記する。
2. **中継ノートに繋ぐ**：MOC直結は大きすぎるが距離1〜2の関連ノートがあるとき、両ノートの「🔗 関連」へ相互リンクを追記する。
3. **容認する**：単発メモなど、リンクが地図を濁すとき。実行記録の容認リストに残し、次回以降に再提案しない。

対話中の接続適用にはユーザー承認を得る。無人実行では候補と判断だけを提案し、適用しない。内容と無関係なリンクを作らない。リンク先の実在をファイル名ベースで確認する。

## 記録と報告

`Inbox/automation/gardener/gardener-YYYY-MM-DD.md` に距離別本数、適用した接続、容認リストを記録する。frontmatter は `summary`、`depth: overview`、手入れした MOC を `related` に含める。到達性統計、適用件数、容認件数、記録ノートへのリンクを報告する。

既存ノートの変更は「🔗 関連」への行追記と MOC クラスタへの行追記だけにする。本文の書き換え、リネーム、削除はしない。主モードは on-demand、定期化は人間が [[SCHEDULES]] の手順で月1回登録する。
