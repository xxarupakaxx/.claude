# セッションの計画と進捗を表示する

実行手順と数値の扱いは[セッションダッシュボード](../../context/session-dashboard.md)を全文読んで適用する。このSkillはReadのみで、HTML保存・検証・起動は呼出元が既存の権限で行う。

1. 最初の具体的な依頼でsession/thread IDと対象を確認し、同じsessionのHTMLを復元、または新規作成する。通常の局所作業も対象。
2. 上部に費用・利用量・進捗のサマリー、その下に状態付きタスク表と質問表を置く。タスク名から詳細プラン・設計・完了条件・検証結果へ移動できるようにする。
3. 費用は既存ローカル記録を調べ、API換算と請求額、累計と期間、取得済みと欠測を区別する。存在する費用を調べずに省略しない。
4. 固定テンプレートを使わず、その作業に合わせて完成したHTMLを直接作る。初版を検証し、OSのデフォルトブラウザの起動コマンドを必ず実行して一度開き、状態の変化と最終報告前に同じfileを更新する。
5. アプリ内プレビューやリンク提示だけでは表示完了にしない。保存、起動要求の成功、実画面の検証を区別して報告する。更新後は同じタブを再読込し、繰り返し新規タブを開かない。

旧Roadmapの表示・同期手順は退役した。`sync-roadmap.py`、generator、Task Hub、workflow MCPを自動起動しない。過去の計画や設計、タスクの状態・未完了gateは保持して新しい表示から参照する。旧parserの機械属性、snapshot、Archify生成を新しいHTMLの作成条件にしない。図が必要な場合は事実に基づいたSVGを使う。

HTML表示は実装・承認・外部公開・Task完了の証拠を代替しない。secretや会話全文を転記せず、外部ロードと実行scriptを含めない。詳しい静的・画面検査は[HTML artifact契約](../../context/html-artifact-contract.md)に従う。
