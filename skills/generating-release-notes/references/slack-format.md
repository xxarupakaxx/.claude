# Slack投稿フォーマットとチャンネル運用

一次情報調査（Slack Help Center / Slack公式エンジニアリングブログ）に基づく判断材料。詳細根拠は `/Users/yoshiki/Notes/Vault/Inbox/knowledge/リリースノート運用_マルチテナントSaaSの一次情報調査.md`（Vault内にある場合）を参照。

## チャンネル選択の判断材料（決定はユーザー、スキルは提示のみ）

| 観点 | 専用チャンネル | 既存チャンネル(`#tha_general`等)への投稿 |
|---|---|---|
| Slack公式推奨 | 全社告知は投稿権限を制限したアナウンス専用チャンネルが良いとされる | 議論用チャンネルは目的別分割が推奨されるが、告知には不向き |
| ノイズ | 低い（告知専用なので受信者の期待が揃う） | 高くなりやすい（雑談・他トピックと混在） |
| 立ち上げコスト | チャンネル作成・周知が必要 | 即座に始められる |

このスキルはチャンネル名をパラメータとして受け取るのみで、新設するかどうかは判断しない。ユーザーが未定の場合は、上表を提示して選んでもらう。

## 投稿テンプレート

```
:sparkles: 今週のリリースノート（<マイルストーン名 or 期間>）

*新機能*
• <ベネフィット要約1文> (対象: <対象範囲>)
  詳細: <Notionページリンク>

*改善*
• <ベネフィット要約1文> (対象: <対象範囲>)
  詳細: <Notionページリンク>

*不具合修正*
• <ベネフィット要約1文> (対象: <対象範囲>)

すべての更新内容: <Notion DBビューへのリンク>
```

## 投稿前チェック

- Step 4（ユーザーレビュー）で確認済みの内容と一致しているか
- `Internal`分類のIssueが混入していないか
- 対象範囲がすべてのエントリに明記されているか
- Notionページへのリンクが有効か（作成済みのURLを使う。推測URLを書かない）
