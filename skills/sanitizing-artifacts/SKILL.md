# 成果物の整形

生成済みの成果物を、制作過程を知らない読者にも自然に読める最終成果物へ整える。

## 既存設定との関係

- Phase 0-5.5 は @context/workflow-rules.md に従う。
- タスクの記録形式は @context/memory-file-formats.md に従う。
- 既存の Skill とルーティングは @context/agent-team-routing.md を正本とする。

## 適用する場面

次の依頼で使用する。

- 現在の作業で生成した成果物を確認、整形、校正、改善、品質確認してほしい。
- 反復的な指示や修正を経た文書を、完成版として整えてほしい。
- 文書、仕様書、ガイド、レポート、画面文言などを対象読者向けに仕上げてほしい。

## 判断基準

会話は制作の文脈であり、成果物の内容ではない。

成果物に残す文を、次の三つに分けて判断する。

1. 読者が成果物を理解、利用、判断するために必要な内容
2. 構成、語調、前提、既定値、例、名称、設計へ間接的に反映する制作上の指針
3. 会話や制作過程に偶然含まれた情報

本文に残すのは1だけである。
2は成果物の設計に反映し、説明としては出さない。
3は削除する。

## 整形手順

1. 成果物の対象読者と目的を特定する。
2. 各文を判断基準で分類する。
3. 読者に不要な制作過程の説明を削除するか、読者向けの内容へ書き換える。
4. 見出し、用語、前提、語調、例の一貫性を確認する。
5. 成果物だけを読んで目的と内容を理解できることを確認する。

## 削除または書き換える表現

次のような内容は、読者に必要な場合を除いて削除または書き換える。

- 依頼、指示、会話、プロンプト、以前の版、修正経緯への言及
- 実装の制約、使用したツール、避けた方法、制作中の判断の説明
- 「依頼に基づき」「指示どおり」「制約のため」「前の版と異なり」のような制作過程を示す表現
- 意図を伝えるためだけに示された例や、修正時のフィードバック
- 成果物の書き方を説明するだけの注釈や免責

制約は通常、本文で宣言せず、構成や具体的な手順に反映する。

## 確認項目

1. 会話を知らない読者にも、独立した成果物として自然に読めるか。
2. なぜこの形にしたかを説明する文が残っていないか。
3. ツール、制約、避けた選択肢への不要な言及がないか。
4. 意図を伝えるためだけの例が本文に混ざっていないか。
5. 複数回の修正による継ぎはぎが残っていないか。
6. 語調、用語、前提、見出しが一貫しているか。
7. 注釈や留保が読者にとって必要な場合だけ残っているか。
8. 一つの自然な書き手の声として読めるか。

## 出力

整形を依頼された場合は、原則として修正後の成果物だけを出力する。

制作過程の説明や、整形した内容の報告を前置きしない。
変更概要も求められた場合は、成果物の後に置く。
