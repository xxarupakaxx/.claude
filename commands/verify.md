# Verify

`verification-loop` のStep 2として使う。checkpointがなければ `/checkpoint` を先に案内し、合格基準を推測で作らない。

## ループ

1. `${MEMORY_DIR}/memory/YYMMDD_<task>/checkpoint.md` を読み、各基準のコマンド・期待値・現在状態を確認する。
2. 基準を実行し、実際の出力、状態（PASS/FAIL/BLOCKED）、実行時点を記録する。
3. FAILの原因を特定する。修正が現在のuser-approved scope内で可逆かつ必要な場合だけ、最小の修正を行う。承認範囲外、外部write、破壊的操作、仕様変更は修正せず、根拠と選択肢を報告する。
4. 影響する基準と回帰確認を再実行し、checkpointを更新する。
5. 全基準がPASSになるか、安全に続けられない理由を記録して終了する。

## 上限と停止

- 最大5 loop。
- 同一エラーの連続失敗は3回で中断。
- LLMによる連続修正は3回で外部フィードバックまたは人間判断へ戻す。
- 修正で以前PASSだった基準がFAILになったら、追加修正を止めて回帰を報告する。

検証を実行したことと、目的の動作が確認できたことを分けて報告する。未実行、環境不足、未確認の基準をPASSにしない。
