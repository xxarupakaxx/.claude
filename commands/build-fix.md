# ビルドエラー修正

ビルド、型検査、コンパイルが失敗し、原因の特定と修正まで必要なときに使う。既存のプロジェクトコマンドを使い、変更範囲と副作用を小さく保つ。

## 進め方

1. プロジェクトの指示と既存の検証コマンドを確認する。最初に失敗したコマンド、終了コード、主要な診断を記録する。`typecheck`や`build`のscriptが存在する場合だけそれを使い、未導入のtoolやscriptを追加しない。
2. 診断を型、import、構文、依存・環境に分類し、同じ原因から派生したエラーをまとめる。
3. 最上流の原因を特定して、関係する行だけを修正する。型の修正や型ガードを優先し、`as`は根拠がある場合に限る。依存の追加や設定変更は、依頼範囲と承認がある場合だけ行う。
4. 最初に失敗したコマンドを再実行し、影響を受ける既存test、typecheck、buildとプロジェクト必須checkを必要な範囲で実行する。失敗が環境や認証に起因する場合はコードの問題と混同せず、再現できた範囲と残課題を分けて報告する。

## 禁止

- `// @ts-ignore`、`// @ts-expect-error`、`any`で診断を隠す。
- エラーと無関係なコードを変更する。
- `tsconfig.json`などのstrict設定を緩めて通す。
- 古い依存や生成物を根拠に成功と判断する。lockfileやcodegenを変更した場合は、プロジェクトの手順に従って必要な再生成・再構築を確認する。

修正後は、何を直したか、実行した検証、環境要因を含む未解決事項を報告する。
